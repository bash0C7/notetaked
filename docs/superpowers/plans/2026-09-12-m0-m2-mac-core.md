# Notetake M0〜M2（bootstrap / NotetakeCore / Mac daemon + app）Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Mac単体で「マイク + システム音声をSpeechAnalyzerでリアルタイム文字起こしし、`<start>.live.txt` / `<start>.timed.jsonl` / `<start>.final.md`へ書き出し、メニューバー常駐appのライブパネルに表示する」ところまでを動かす。

**Architecture:** SwiftPMの`NotetakeCore`（モデル・NDJSON・Reconciler・Renderer・SessionStore・制御メッセージ・Transcriber wrapper）を土台に、CLI daemon `notetaked`が音声取得→認識→集約→ファイル書き出しのハブになり、XcodeGen生成のmacOS app `Notetake`が子processとしてdaemonを起動してstdin/stdoutのNDJSONで制御・表示する。iOS / watchOS appはM0で空のskeletonだけ作る。

**Tech Stack:** Swift 6.3 / SwiftPM / XcodeGen / SwiftUI(`MenuBarExtra`) / Speech(`SpeechAnalyzer`, `SpeechTranscriber`) / AVFAudio / CoreAudio process tap / swift-argument-parser / Swift Testing(`import Testing`)

**Spec:** `docs/superpowers/specs/2026-09-12-notetake-design.md`

**モデル分担（userの指定）:** 各taskの実装はSonnet subagent、`swift build` / `swift test` / `xcodegen` / `xcodebuild` / `say`等の決定論的コマンド実行はHaiku subagent、レビュー・統合・commitはFable（本session）。このため本計画は「正確なinterface・test仕様・受け入れ条件」を書き、実装コード本体は各taskの実装者が書く。

## Global Constraints

- platform floor: macOS 26.0 / iOS 26.0 / watchOS 26.0（Package.swiftとproject.ymlの両方）。Swift language mode 6（strict concurrency）
- 外部依存はswift-argument-parser（daemonのみ）だけ。M3でFluidAudioを`NotetakeDiarization` targetに足すまで他は追加しない
- 全platform共有の`NotetakeCore`にはmacOS専用API（CoreAudio process tap、AppKit）を入れない。Speech / AVFAudioは`#if canImport(Speech)`で囲む
- ファイル接頭辞は録音開始のローカル日時`yyyy-MM-dd_HHmmss`（例: `2026-09-12_143005`）。出力は`<prefix>.live.txt` / `<prefix>.timed.jsonl` / `<prefix>.final.md`
- NDJSONのkeyはsnake_case、型判別keyは`t`。segは`t:"seg"`、他は`session` / `device` / `speaker_name`
- 時刻は全てepoch ms（Int64）。表示時のみローカル時刻に変換
- bundle id: `io.github.bash0c7.notetake`（mac）/ `io.github.bash0c7.notetake.ios` / `io.github.bash0c7.notetake.ios.watchkitapp`。Team `SM5792D355`
- テストはSwift Testing（`@Test`, `#expect`）。純粋ロジックはTDD（失敗するテスト → 実装 → 通過 → commit）
- commit messageの末尾に次の2行を付ける:
  `Co-Authored-By: Claude Fable 5.1 <noreply@anthropic.com>` / `Claude-Session: https://claude.ai/code/session_01UV69JxKMEVTet7hZ1sdkgc`

**Interfaces（Produces）:**

```swift
public enum Platform: String, Codable, Sendable { case mac, ios, watchos }
public enum Source: String, Codable, Sendable { case mic, system, watch }

public struct SpeakerTag: Codable, Sendable, Equatable {
    public var local: String?        // stream内のlocal id（話者分離が付ける、M3）
    public var global: String?       // Mac側SpeakerRegistryが付けた大域id（M3）
    public var embedding: [Float]?   // 256次元（M3）
    public init(local: String? = nil, global: String? = nil, embedding: [Float]? = nil)
}

public struct Segment: Codable, Sendable, Equatable, Identifiable {
    public var id: UUID
    public var session: String
    public var seq: Int
    public var device: String
    public var deviceName: String     // key: device_name
    public var owner: String          // 話者の既定ラベル。systemは"リモート"
    public var platform: Platform
    public var source: Source
    public var start: Int64           // epoch ms（デバイス時計）
    public var end: Int64
    public var text: String
    public var confidence: Double?
    public var levelDBFS: Double?     // key: level_dbfs
    public var speaker: SpeakerTag?
    public var clockOffsetMS: Int64   // key: clock_offset_ms、Macが受信時に付与。既定0
    public var receivedAt: Int64?     // key: received_at
    public init(...)                  // 全fieldをlabel付き引数、optionalは既定nil、clockOffsetMSは既定0
}

public struct SessionRecord: Codable, Sendable, Equatable { public var id: String; public var started: Int64; public var owner: String }
public struct DeviceRecord: Codable, Sendable, Equatable { public var device: String; public var deviceName: String; public var owner: String; public var platform: Platform; public var offsetMS: Int64 }  // keys: device_name, offset_ms
public struct SpeakerNameRecord: Codable, Sendable, Equatable { public var speaker: String; public var name: String }

public enum Record: Codable, Sendable, Equatable {
    case session(SessionRecord)          // t: "session"
    case device(DeviceRecord)            // t: "device"
    case speakerName(SpeakerNameRecord)  // t: "speaker_name"
    case segment(Segment)                // t: "seg"
}

public enum NDJSONError: Error, Equatable { case unknownType(String) }
public enum NDJSON {
    public static func encode(_ record: Record) throws -> String   // 1行・改行なし・keyはsorted・非ASCIIはそのまま・"/"はescapeしない
    public static func decode(_ line: String) throws -> Record
    public static func decodeAll(_ text: String) -> [Record]      // 空行と壊れた行（途中で切れた最終行など）は捨てる
}
```

実装の要点: `Record`のCodableは`t` keyを`CodingKeys`で読み書きし、payloadは同じencoder / decoderに`encode(to:)` / `init(from:)`で平坦に載せる（JSONEncoderは同一containerへの追記でkeyが合流する）。CodingKeysはsnake_caseを明示する（`convertToSnakeCase`に頼らない）。encoderは`.sortedKeys, .withoutEscapingSlashes`

```swift
    public var end: Int64

    public var confidence: Double?
    public var source: Source      // 採用本文のsource
    public var ownerLabel: String  // 採用本文segのowner
    public var sources: [UUID]     // 統合したseg id（受信順）
    public var devices: [String]   // 統合したdevice id
}

public struct Reconciler: Sendable {
    public struct Config: Sendable {
        public var overlapRatio: Double = 0.5
        public var toleranceMS: Int64 = 1000
        public var textThreshold: Double = 0.5
        public init()
    }
    public init(config: Config = Config())
    public private(set) var utterances: [Utterance]          // start昇順
    public private(set) var speakerNames: [String: String]   // 大域id → 名前
    /// 1 recordを適用し、追加・変更されたutteranceを返す
    @discardableResult public mutating func apply(_ record: Record) -> [Utterance]
    public static func fold(_ records: [Record], config: Config = Config()) -> [Utterance]
}
```

**規則（この通りに実装する）:**
1. `.session` / `.device` → 何もしない、`[]`
2. `.speakerName(n)` → `speakerNames[n.speaker] = n.name`。`speakerID == n.speaker`の全utteranceのラベルを更新して返す
3. `.segment(s)`:
   - 既に`sources`に`s.id`を含むutteranceがあれば無視（冪等）→`[]`。`text`が空白のみなら無視
   - `start' = s.start + s.clockOffsetMS`, `end' = s.end + s.clockOffsetMS`
   - 候補: `devices`に`s.device`を含まないutteranceのうち、`min(u.end, end') + tol - max(u.start, start') >= overlapRatio * max(1, min(u.end - u.start, end' - start'))`かつ`bigramDice(u.text, s.text) >= textThreshold`。複数なら重なり（`min(end) - max(start)`）最大のもの
   - 候補あり → 統合: `sources += [s.id]`, `devices += [s.device]`, `start = min`, `end = max`。本文は`(confidence ?? 0, priority(source), text.count)`の辞書順比較で大きい方（priority: system=3, mic=2, watch=1）。sが勝てば`text / confidence / source / ownerLabel`を差し替え。`speakerID == nil`かつ`s.speaker?.global != nil`なら`speakerID`を設定。ラベル再計算
   - 候補なし → 新規utterance（`id: s.id`, `speakerID: s.speaker?.global`, `ownerLabel: s.owner`, `sources: [s.id]`, `devices: [s.device]`）をstart順を保って挿入
   - ラベル: `speakerNames[speakerID] ?? speakerID ?? ownerLabel`
   - 返り値は追加・変更した1件
4. `fold`は空のReconcilerに順に`apply`して`utterances`を返す
