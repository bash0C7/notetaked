# 収録の「区切る」・ライブパネル操作・自動区切り Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** 収録を終了して新しい接頭辞で作り直す操作「区切る」（daemon command `rotate`）をメニューとライブパネルに置き、ライブパネルから収録開始・停止もできるようにする。常駐で収録し続けた時のメモリ増加対策として「自動で区切る間隔」（時間、小数可、既定24、0で区切らない）を設定に持つ。

**Architecture:** daemon（`ServeSession` actor）に`rotate`を追加し、actor内でstop→startを一括実行して新prefixの`status`だけを出す（中間の停止statusを出さないので、appの`restartPending`再起動と競合しない）。自動区切りのタイマーはapp（`AppModel`）側に置き、`NotetakeCore`の純粋関数`RotationSchedule`で期限を計算する（設定変更の即時反映のため）。

**Tech Stack:** Swift 6 / SwiftPM / SwiftUI / Swift Testing。M0〜M2と同じ。

**Spec:** `docs/superpowers/specs/2026-09-12-notetake-design.md`

**環境:** 本計画の実装セッション（Claude Code on the web、Linux）にはSwiftツールチェーンが無い。テストは先に書き、`make test` / `make app` / 実機確認はMac側セッションで行う（HANDOFF.md「Mac側で行う検証」）。

**モデル分担:** コード記述=Sonnet、決定論コマンド=Haiku、検討・統合・review=Fable（CLAUDE.md）。

### Task 3: `ServeSession.rotate()`

**Files:** Modify `Sources/notetaked/Pipeline/ServeSession.swift`

**要件:**
- `start()`を`startCapture() async -> Bool`（store作成〜streams起動〜state更新。失敗時はerror送信して`false`）と、`start()`（`guard !recording` → 成功時`status(recording:true)`）に分割
- `stop()`を`stopCapture() async`（streams停止〜final書き出し〜close〜state reset）と、`stop()`（guard → `status(recording:false)`）に分割
- `rotate()`: `guard recording, store != nil`（else `error("not recording")`）→ `stopCapture()` → `startCapture()`成功なら`status(recording:true, prefix: new, sources:)`と`log("rotated <old> -> <new>")`、失敗なら`status(recording:false)`
- prefix衝突回避: `lastPrefix`を保持し、`startCapture`で`SessionStore.prefix(for:timeZone:)`が`lastPrefix`と同じ間は開始日時を1秒進める
- `handle(_:)`に`case .rotate`。`quit()` / `ServeCommand`は変更なし

- [ ] **Step 1: 実装**
- [ ] **Step 2: Mac側でCLI e2e**（HANDOFF「Mac側で行う検証」3）
